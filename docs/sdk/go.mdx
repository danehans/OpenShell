Use the Go SDK to manage OpenShell resources from Go applications, operators,
and controllers. Its typed subclients follow familiar Kubernetes client
patterns. Use the SDK and gateway from the same OpenShell release when possible.

## Install the SDK

The SDK requires Go 1.25.13 or later. Add it to your Go module:

```shell
go get github.com/NVIDIA/OpenShell/sdk/go@latest
```

## Connect to a Gateway

Pass a `host:port` address to `NewClient`. For a local gateway that allows
unauthenticated plaintext connections:

```go
package main

import (
    "context"
    "fmt"
    "log"
    "time"

    v1 "github.com/NVIDIA/OpenShell/sdk/go/openshell/v1"
)

func main() {
    client, err := v1.NewClient(v1.Config{
        Address: "127.0.0.1:8080",
        Auth:    v1.NoAuth(),
    })
    if err != nil {
        log.Fatal(err)
    }
    defer client.Close()

    ctx, cancel := context.WithTimeout(context.Background(), 2*time.Minute)
    defer cancel()

    health, err := client.Health().Check(ctx)
    if err != nil {
        log.Fatal(err)
    }
    fmt.Printf("gateway healthy: %v\n", health.Healthy)
}
```

For an authenticated TLS gateway, provide the bearer token and TLS settings:

```go
client, err := v1.NewClient(v1.Config{
    Address: "gateway.example.com:443",
    Auth:    v1.StaticToken(os.Getenv("OPENSHELL_TOKEN")),
    TLS:     &v1.TLSConfig{CAFile: "/path/to/ca.crt"},
})
```

Omit `CAFile` to use system roots. For renewable OIDC service credentials, use
`oidc.NewClientCredentialsAuth` from
`github.com/NVIDIA/OpenShell/sdk/go/openshell/v1/oidc`.

## Create and Use a Sandbox

Resource methods take an explicit workspace. The following example creates a
sandbox in `default`, waits for readiness, runs a command, and requests
deletion:

```go
sandbox, err := client.Sandboxes().Create(
    ctx,
    "default",
    "sdk-example",
    &v1.SandboxSpec{
        Template: &v1.SandboxTemplate{
            Image: "registry.example.com/team/python-agent:1.0",
        },
    },
    nil,
)
if err != nil {
    log.Fatal(err)
}

sandbox, err = client.Sandboxes().WaitReady(ctx, "default", sandbox.Name)
if err != nil {
    log.Fatal(err)
}

result, err := client.Exec().Run(
    ctx,
    "default",
    sandbox.Name,
    []string{"python", "-c", "print('hello from OpenShell')"},
)
if err != nil {
    log.Fatal(err)
}
fmt.Print(string(result.Stdout))

if _, err := client.Sandboxes().Delete(ctx, "default", sandbox.Name); err != nil {
    log.Fatal(err)
}
```

## Stop a Specific Execution

Use `StopSandboxExecution` for an automated response tied to one runtime
execution. Capture `sandbox.Status.ExecutionID` when you observe the event;
do not replace it with a newly fetched identity when handling a delayed event.

```go
receipt, err := client.StopSandboxExecution(
    ctx, "default", sandbox.Name, sandbox.Status.ExecutionID,
    v1.StopExecutionOptions{RequestID: requestID},
)
if err != nil {
    log.Fatal(err)
}
fmt.Printf("execution %s: %s\n", receipt.ExecutionID, receipt.Phase)
```

`requestID` is an optional nonzero UUID persisted with the operation and reused
only for retries of that same request. The receipt describes the original
execution, including on replay. A stale identity fails with `FailedPrecondition`;
an older gateway returns `Unimplemented`. The SDK never falls back to `Stop`.
The in-memory fake returns `Unimplemented` because it does not model durable
execution identity. Conditional stop currently supports a single gateway using
SQLite; PostgreSQL and multi-replica deployments reject it with
`FailedPrecondition`. See [Stop a Specific Execution](/how-it-works/sandboxes/overview#stop-a-specific-execution).

The root client also exposes subclients for providers, services, files, SSH,
TCP forwarding, policy, configuration, templates, and workspaces. List methods
return lazy pagers so callers choose when to fetch the next page.

## Hold Runtime Admission (Experimental Fork)

This fork adds `client.Admission()` for workspace administrators to prevent a
sandbox from starting another execution. Use the matching fork SDK and gateway;
older gateways return `Unimplemented`. All gateway replicas serving the sandbox
must support admission holds. Do not roll back to an older gateway while holds
exist: older servers cannot enforce the new state.

Read the current state using the canonical name and immutable sandbox UUID:

```go
state, err := client.Admission().Get(ctx, "default", sandbox.Name, sandbox.ID)
if err != nil {
    log.Fatal(err)
}
receipt, err := client.Admission().Hold(
    ctx, "default", sandbox.Name, sandbox.ID,
    actionID, state.Epoch, v1.AdmissionIncident,
)
if err != nil {
    log.Fatal(err)
}
fmt.Printf("admission hold recorded at epoch %d\n", receipt.Epoch)
```

Persist the nonzero UUID `actionID` and complete request before sending it. Retry
that same request unchanged after an uncertain outcome, or query `Receipt` with
its action ID. A receipt describes the original mutation; use `Get` to observe
current holds. A stale epoch or changed resource identity fails explicitly.

`Release` requires a distinct persisted action UUID, the original hold UUID and
the current epoch. It removes only that hold and never starts compute. Other
holds continue denying launch. A hold cannot confirm while a launch is unsettled;
legacy Ready sandboxes must complete a tracked lifecycle transition first.

Admission holds do not stop an existing execution, isolate network traffic or
prevent deletion and recreation under a different sandbox UUID. Pair them with
separately verified containment and conditional stop when those actions are
required. Receipt history is bounded; a full history rejects new holds without
evicting original receipts or consuming outstanding release capacity.
